# 京漫便民：真实接入资料与开发清单

日期：2026-09-17。当前交付为 Windows 微信开发者工具人工验收版。

当前可运行的订单、库存、优惠、退款和审计使用真实 SQLite；对外支付、配送、打印与收银协议均为本机模拟。以下项目不是填几个密钥就能自动完成，须按接口实现、联调并验收。

## 一、微信小程序身份与发布

需准备：拥有开发权限的 AppID、主体及类目资质、账号管理员和开发者/体验者名单、隐私保护指引、客服电话、商家名称和地址、合法素材授权、版本说明及备案/审核所需材料。具体要求以微信后台显示为准。

需开发：以 wx.login 的临时 code 换取服务端身份；自有会话与到期处理；服务端绑定员工角色和门店；移除任意选择演练角色的登录接口；用户注销及个人信息删除流程。AppSecret 只能放服务端，不能写进小程序或 Git。

需验收：开发者工具、微信体验版、iOS/Android真实手机、首次/重复登录、会话过期、账号切换、隐私提示及拒绝授权路径。

## 二、真实微信支付与退款

需准备：已开通相应支付产品并绑定小程序的商户号、AppID、API v3 密钥、商户私钥及证书序列号、平台证书或微信支付公钥及对应ID、HTTPS支付/退款通知地址、商户联系人、对账账户和测试授权。服务商模式另需服务商与子商户资料。密钥须存安全的服务端配置中。

本版已落地的接口边界：

| 位置 | 当前行为 | 真实接入工作 |
| --- | --- | --- |
| `miniprogram/utils/payment.js` | 只调用明确标识的模拟支付 | 获取后端签名的支付参数，调用官方支付API，完成后再查询服务器；不可凭前端成功回调改已付款 |
| `POST /api/payments/{order_id}/simulate` | 模拟扣款并走现有签名事件、订单与库存事务；重复调用只记一笔 | 正式环境必须禁用此路由 |
| `GET /api/payments/{order_id}` | 只允许订单所属顾客查询本地付款/退款状态 | 增加上游查单和对账结果，处理结果未知与关单 |
| `POST /api/payments/{order_id}/prepay` | 明确返回503未配置，不假造微信参数 | 服务端核价、调用预支付、签名、返回支付参数；真实请求不得采用客户端金额 |
| `POST /api/payments/wechat/notify` | 明确返回503，不接受伪造到账 | 校验平台签名、时间与证书，解密通知，核对商户、AppID、币种、金额、订单、交易号，幂等入账后正确应答 |
| `POST /api/payments/wechat/refund-notify` | 明确返回503，不接受伪造退款 | 退款通知验签解密、核对原交易和退款单、幂等更新退款流水 |
| `backend/payment_ports.py` | 模拟支付适配实现与创建/查询协议 | 实现真实提供方；本版不允许通过配置开关直接变为真实支付 |
| `backend/service.py` 退款任务 | 本地模拟退款、失败重试、金额与流水对账 | 抽出真实退款提交/查单适配；任务幂等、查询未知结果、通知验签、对账与人工处理 |

需验收：成功、拒付、用户取消、断网、重复/乱序通知、超时后到账、重复提交、全额/部分退款、退款超时恢复、证书轮换、金额不符拒绝、账单对账。模拟使用的HMAC不是微信支付API v3验签方案。

## 三、商家收银/POS/库存系统

先由商家确认具体产品：拉卡拉云零售、聚合收款、其他POS软件的接口不相同。需要厂商现行接口文档与版本、测试环境、门店ID、接入ID、授权范围、双方签名公钥/私钥管理方案、请求频率、分页/增量游标、SKU/条码/多规格/称重单位与库存口径。

本次核对的公开参考：

- 商品接口：https://yxd.lakala.com/fbbc-school-docs/openapi/goods.html
- 签名规范：https://yxd.lakala.com/fbbc-school-docs/openapi/spec.html

当前实现是 `POST /b2c-oms-server/productShop/barcodeQuery` 的单门店条码查询子集。请求/响应按原始JSON做RSA签名和验签，使用自行生成的模拟密钥。支持正常、空结果、业务拒绝、签名错误、流水号错误、过期、HTTP异常与超时。端口8873只监听127.0.0.1，不能用它替代真实厂商服务器。

`backend/lakala_mock.py` 为本地模拟；`backend/lakala_readonly.py` 为严格关闭默认执行的真实测试只读适配位置。Windows 兼容读取只用于模拟模块；真实凭据读取仍要求原来的受控运行环境，正式 Windows 凭据存储还需实现并验证 ACL/密钥管理。

特别区分：条码查询仅展示外部模拟结果，不自动导入、不覆盖现有库存。库存页“模拟POS出库”记录本系统库存流水，用于验证线下销售减少可售库存；它不是厂商订单写回API。本轮不虚构未确认的厂商写接口。

后续开发：完整商品导入及异常人工审核、增量同步、线下销售/退货事件、在线预占与POS库存协调、订单写回、冲突解决、版本控制、断网补偿与对账。真实经营库首次导入必须备份并演练恢复，不能用快照覆盖正在营业的账本。

## 四、配送、打印、消息

配送需商家确认范围、起送、基础运费、满额免运费口径、重量和取整、时段、取消费用、骑手权限及配送供应商协议。真实计费重量需逐SKU核实；商品名中的毫升不能直接当克重。

打印需设备型号、厂商协议、设备ID/授权、票据模板、打印状态回调及重复任务规则。当前为模拟小票和任务队列。

消息需微信订阅消息模板、订阅授权与拒绝路径、订单事件映射。当前通知保存在本地数据库，不实际推送微信。

## 五、服务器与运维

需准备：受控服务器或云开发环境、HTTPS域名和证书、微信合法域名、数据库和文件存储、备份目录、运维负责人、监控与告警、日志保留期限、访问控制及密钥轮换方式。

需开发与验收：关闭实验室入口/模拟支付/故障开关、服务端员工授权、防重放与限流、最小日志、备份恢复、发布回滚、容量与稳定性、依赖漏洞修复及独立安全审查。SQLite是否替换应由真实并发、部署方式和持久化需求决定。

不要直接把本地8873/8874端口映射到公网。本次只在开发者工具模拟器使用电脑本机地址；手机中的127.0.0.1不是电脑。

## 六、接入验收交付物

每个真实服务应留下：厂商文档版本、授权证明、配置清单（不含明文密钥）、调用/回调脱敏证据、失败恢复结果、账单核对、负责人和上线回滚步骤。填写资料不等于接入完成；以真实环境成功与异常路径验收为准。
