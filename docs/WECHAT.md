# 微信端联调说明

## 已交付

15 个原生 Page，使用 WXML/WXSS/JavaScript 和统一 `utils/api.js`。金额显示、角色边界与服务端订单状态复用相同契约。静态检查包括文件、路由、WXML事件处理器、import/include引用与标签结构；控制器测试把 `wx.request` 映射到真实 HTTP，调用的是交付目录里的实际 Page 代码。

## 导入步骤

1. 在电脑运行根目录 `bash run.sh`，保留后端进程。
2. 用微信开发者工具导入 `miniprogram/`，按工具要求设置自己的测试 AppID；项目的 `touristappid` 仅为占位。
3. 本机模拟器可以使用 `http://127.0.0.1:8765`。项目中的域名校验关闭开关仅用于这一开发环境，不用于正式发布。
4. 在连接页输入终端给出的口令，选择顾客或店员身份。所有订单在同一份 SQLite 中，网页与小程序共享业务状态。
5. 按 README 的配送/自提路线测试。店长可以在网页中配置门店规则，在原生工作台中处理订单与库存。

## 必须在微信环境单独验收

初版交付时没有执行微信开发者工具编译、WXML/WXSS 渲染、iOS/Android真机、正式小程序登录、微信支付、微信订阅消息、发布审核、授权弹窗和弱网恢复。初版验收矩阵中的记录属于该次交付，不会因为 Node Page 控制器测试通过就自动变绿。

2026-09-13 补充本机验收：在 Linux 社区移植版开发工具 `2.02.2608070`、基础库 `3.17.3`、游客模式中，独立副本 `/home/vimalinx/MakeMoney/SuperMarket/jingman-devtools-linux-playground` 已完成实际编译/渲染，连接独立 8767 测试后端；首页、商品详情、购物车、结算、订单详情及页面模拟支付得到实际观察。创建订单使用开发工具 Console 连续调用页面原有报价刷新和提交方法，以避免逐步截图超过两分钟报价时限，因此不把它算作完整纯点击验收。最终示例自提订单 30.74 元，页面为“待接单”，SQLite 为 `paid`，模拟支付台账一致。75 个业务/资源文件与本工程一致；仅独立副本配置不同。

Linux 安装修复记录和截图见 `/home/vimalinx/.local/opt/wechat-devtools-2.02.2608070-1.srnaXC/INSTALLATION.md`。此结果不等于腾讯官方 Linux 支持或真机验收；后台窗口的首次点击/刷新偶有滞后，仍需继续验证。正式微信身份、真实支付、订阅消息、真机与发布审核仍未执行，商家正式数据未用于这次演练。

实际手机上的 localhost 不等于开发电脑。真实手机联调需要有受控的测试服务、正确域名/TLS和测试身份体系；本包刻意不提供一键公网开放实验室的方法。正式集成时必须移除可任意切换身份的实验室入口，而不是只隐藏它的按钮。
